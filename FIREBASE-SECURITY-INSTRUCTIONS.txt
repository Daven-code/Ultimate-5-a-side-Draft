WHY THIS PREVENTS THE SAME LOSS
- There is no write permission at /leaderboard itself.
- Writes are granted only at /leaderboard/$entryId.
- !data.exists() allows creation only, so existing scores cannot be overwritten.
- newData.exists() prevents deletion.
- Validation rejects malformed records such as a lone test timestamp.

LIMITATION
Because the public site has no user authentication or trusted server, public clients can still attempt to append valid-looking entries. The rules prevent replacement and deletion of historical scores. Strong anti-cheat protection would require Firebase Authentication, App Check, or a server-side submission endpoint, which would be a separate functional architecture change.

ROOMS AND STATS
The current online-room and statistics permissions are retained to avoid changing any game-mode functionality. These areas remain more permissive than ideal and should be hardened separately with authentication/App Check after the leaderboard has been restored and tested.
